# 法規自動檢索（Regulation Watch）

每週自動檢查本工具依據的各項法規來源是否有變動，若偵測到變動，自動開啟一個 GitHub Issue 提醒你人工確認。

## 運作方式

1. **排程**：`.github/workflows/regwatch.yml` 設定每週五 04:00（台北時間）自動執行，也可在 GitHub 的 Actions 分頁手動觸發（Run workflow）。
2. **檢索**：`check_regulations.py` 抓取 `baseline.json` 列出的各法規來源頁面，計算內容雜湊並與上次比對。
3. **通知**：偵測到變動時產生 `changes.md`，並由 workflow 自動開成標記 `regulation-watch` 的 Issue。
4. **人工把關**：**腳本只偵測、不自動改程式**。法規判讀有模糊空間，須由你確認實質異動後，再手動更新 `app.js`、`templates.js`、`references.js` 與 `baseline.json`。

## 檔案

| 檔案 | 用途 |
|------|------|
| `baseline.json` | 法規基準清單（來源網址、目前版本、關鍵字） |
| `check_regulations.py` | 檢索與比對腳本 |
| `hashes.json` | 各來源上次的內容雜湊（自動產生，首次執行後出現） |
| `changes.md` | 最近一次比對結果（自動產生） |

## 首次啟用注意

1. 第一次執行只會**建立基準雜湊**，不會報變動（因為沒有前次可比）。第二週起才會真正比對。
2. 部分政府網站（如全國法規資料庫、金管會）可能對自動化請求回傳 403。腳本已加上瀏覽器標頭降低機率；若某來源持續 403，會列為「無法連線」而非「變動」，不會誤報。建議偶爾手動到該來源確認。
3. 需在 repo 的 Settings → Actions → General 中，將 Workflow permissions 設為 **Read and write permissions**，Issue 自動建立才會成功。

## 調整檢查頻率

編輯 `.github/workflows/regwatch.yml` 的 cron 值。注意 GitHub Actions 使用 UTC：
- 台北週五 04:00 = UTC 週四 20:00 → `0 20 * * 4`
- 若要改成每天 → `0 20 * * *`
